# SLEAPの検出を固定して2D追跡を比較する計画

日付：2026-09-16。状態：コード・保存データの調査と人手レビューの記録を完了。
新しい2D追跡方式の比較実験・本番適用はまだ行っていない。

## 判断

独自2D追跡には改善余地がある。特に、低い類似度でも接続を確定する現行設定に対し、
前後の運動、接続の曖昧さ、見失っていた時間を扱える利点がある。
ただし、SLEAPより高性能であることは未検証。検出器は現在のSLEAPのまま固定し、
時間方向の接続だけを交換可能にする比較が適切である。

元C27/C28との追加照合では、**SLEAPの同一ID内の飛びと、3D側の対応・後処理による飛びが混在**していた。
f76235には元2D ID内部の大移動がある一方、f30735はside2の同じ2D IDを別slotへ割り当て直している。
f31479付近ではC28の31481に約173 mmの飛びがあり、C34では31479に約175 mm、31497に約171 mmの飛びとなる。
それぞれの境界で元2Dの同一ID内の移動は小さく、3D対応とその後のID処理を併せて調べる必要がある。
したがって、独自2D追跡だけを替える計画では、今回の失敗を全て解決できない。

今回見つかったスワップを全てSLEAP由来とは断定しない。
検出行内の部位混在、視点間対応、時間方向の2Dラベル、最終3Dのslot IDは別々の問題である。
保存C34の `source` はフレーム内の検出行番号であり、元のC27の2D tracklet IDではない。

## 現行コードで確認したこと

1. `c27` は `c24.run_tracker` 経由でSLEAPの時間追跡を使用する。
   口＋胸びれ、OKS、各trackの過去5観測のlocal queues、Hungarian割当、track数上限なし。
   node別scoreは1で渡しており、検出scoreやmatching scoreをID正解確率とは解釈できない。
   現行設定では画像・optical flow・Kalmanを使用していない。
   現環境のSLEAP自体にはこれらの選択肢があるため、ライブラリ全体の欠点とは言わない。
2. `c25`/`c28` は3視点ラベル組が変わったslot数にλを課す。
   SLEAP IDは固定条件ではなく有限の罰則である。フレーム内は幾何と観測不足で評価する。
   ただし同じ2Dラベルの内部で魚が入れ替わると、ラベル不変のまま誤った連続性を持ち込める。
   現在のtransitionに位置・進行方向の連続性は入っていない。
3. 同じ検出行の口・胸びれは一体で扱われるため、時間IDの変更だけでは部位混在は直らない。
   また未割当行の除外と、ラベル組へのsoft penaltyは区別する必要がある。

コード根拠：[`c24`](../../tools/c24_uncapped_tracklets.py)、
[`c27`](../../tools/c27_uncapped_tracklets_any.py)、
[`c25`](../../tools/c25_variable_cardinality.py)、
[`c28`](../../tools/c28_lambda_grid_transfer.py)。
標準のSLEAPでも検出後の追跡は分離されている：
[公式tracking guide](https://github.com/talmolab/sleap-nn/blob/main/docs/guides/tracking.md)。

## 前に試した方式との違い

独自の [`track2d.py`](../../src/medaka3d/track2d.py) は既にある。
隣接2フレームの胸びれ点の割当を比較して曖昧なら切るが、ちょうど3検出が揃う場合だけを扱う。
速度予測、逆方向照合、可変検出数、欠測後の回復はなく、現在のC27はこの方式を使っていない。
以前の比較では短いtrackletが多く、単純に戻す根拠はない。

C24bでは既に大きな2D移動のリンク2206本を切っている。
当時のλ=2のfemale gated評価では263維持/34分断/1スワップから265/32/1となり、
スワップ数は変わらなかった。これは現在の全slot ID評価とは異なる過去の指標である。
今回試すべき追加要素は、距離だけでなく**前後の予測と曖昧さを使う接続判断**である。

過去の50フレーム多数決は、幾何指標が改善してもfemaleスワップを増やした記録がある。
長い平滑化やID固定を改善の代用にしない。
出典： [2D-firstの記録](2026-08-18-2d-first-tracking.md)、
[C24/C24bの記録](2026-08-25-uncapped-tracklets.md)。数値は当時の報告として引用し、新規に再測定したものではない。

## f31479が残っている理由

元C28との比較で、問題の大きさが後段で変わることも確認した。
各行はそのstageのslot順であり、stage間の同じslot番号が同じ個体を意味するとは限らない。

| 境界 | C28の各slotの3D移動 mm | C34の各slotの3D移動 mm |
|---|---|---|
| 31478→31479 | 1.02 / 12.08 / 0.20 | 174.92 / 172.92 / 0.20 |
| 31480→31481 | 173.63 / 173.15 / 0.39 | 3.33 / 3.53 / 0.39 |
| 31496→31497 | 0.94 / 0.79 / 1.07 | 170.57 / 171.04 / 1.07 |

入口での元C27同一ID内の口・胸びれ移動の最大は、top 18.07 px、side1 2.78 px、side2 4.52 px。
出口でも全視点の最大は8.03 px。C28は出口で2Dラベル組を変更していない。
この境界の約170 mmの飛びを、元SLEAP ID内部の飛びとして扱うのは不適切である。
C28の31481の大移動でも、元C27同一ID内の最大はtop 5.61 / side1 2.34 / side2 3.98 px。
C28にも大移動があるため、C34後処理だけを唯一の原因とするのも不適切である。
一方、入口C28のtopのラベル選択変更や12.08 mmの移動、付近の2D不整合は残っており、
上流が全て正しいという意味でもない。
2Dで重なった魚の誤接続は小さな移動でも起こり得るため、2D移動量が小さいだけでIDの正しさを保証しない。

保存C34を読み直すと、S0/S1の交換は31479–31496の18フレームで、31497に戻る。
入口の移動は174.92/172.92 mm、出口は170.57/171.04 mm。
過去の「31479を修復」という記録は、同じ文で「31497からID復旧」と限定されている。

- C33は疑わしい視点を除外する座標修正で、IDを変更しない。
- C30のzone auditは異常区間を出た後の `perm[t1:]` を変更する。区間内部を再追跡しない。
- C34の往復交換修復は最大3 resolved frames。18フレームの交換は対象外。
- 今回の双方向処理は31476–31483の候補で `invalid_independent_flank` として拒否。
  左参照31459–31475に12.81 mmのジャンプ、右参照31484–31500に31497の約171 mmの戻りが含まれる。
  異常を小さく分けた結果、異常自身が前後参照に入っていた。

保存配列を変更せず31479–31496だけS0/S1を交換する仮説を計算すると、
入口は2.61/12.08 mm、出口は0.79/0.94 mmに下がる。
**3Dから直せないのではなく、異常区間の内部を修復する処理が足りない。**
ただし入口の12.08 mmは残るので、ラベル変更だけで座標も正常化したとは言えない。

C33について保存2D点からdrop-viewを再計算したところ、31479 S0で最良0.18168 mm、
次点0.36895 mm、差0.18727 mmとなり、必要な1 mm差を満たさない。
これは元のC33 runログではなく、現在の保存点による再現診断である。

## 次の比較実験

### 1. 失敗を最初に生じた段階を特定

今回の20秒75270:78590と、今回の8場面・既知例について、
各視点の検出行→C27の2D ID→C28の3視点対応→最終slotを並べる。
元のC27/C28出力を確認してから、2D内部の誤接続か、視点間対応か、部位混在かを分類する。
現在ローカルstagingにあるC01/C34だけではこの帰属は確定できない。
元のC27 serialラベル3視点とC28 λ=.767は、設定済み共有 `work_dir` に存在することを確認した。
短区間だけSLEAPを再起動して履歴を変える必要はない。

今回8場面の各±40フレームについて追加照合を実行した。代表的な観測は以下のとおり。

| 場面 | 元2Dラベルと選択点の観測 | 改善を試す段階 |
|---|---|---|
| 76235 | topで同一C27 ID=1の口76.38 px・胸びれ66.91 pxの移動。side2ではID=2/1のslot割当も交換。 | 2D接続と3視点対応の両方。 |
| 30735 | side2のC27 ID=0がS1からS0へ割当変更。元の同一IDの座標は大きく飛んでいない。 | 3視点対応・欠測時の割当。 |
| 76930 | side2でS0/S1に選ばれるC27 ID=0/2が交換。 | 元2D IDをどう3D slotへ接続するか。 |

これらは追跡処理の段階を切り分ける観測であり、2Dラベル一致だけを生物学的ID正解とはしない。
76988の中心でのラベル不変も、重複するレビュー動画全体がスワップなしであることを意味しない。

最終的な根拠は [段階別診断v2](../../work/multiview_node_review_v1/human_review_followup/stage_a_review_audit_v2.json)
（主要境界は `key_edges`）と [再現スクリプト](../../labs/20260916_multiview_node_review/audit_reviewed_stage_a.py)。
3視点とも現行共有C01とローカルC01のSHA256は一致し、C27ラベルとの行数・フレーム順を確認した。
元C27のprovenanceには入力SHAが記録されていないため、当時の入力までのハッシュ証明はできない。
診断の読戻し、コード・出力ハッシュ、Ruffは確認済み。

f31479では関連するジャンプと戻りを一つの異常区間へまとめ、
その外側の安定区間を前後参照に取る。固定の小窓のまま拒否閾値を緩める方法は取らない。
この区間内修復は、2D追跡方式の比較と別条件で検証する。

### 2. 検出を固定した3条件

| 条件 | 2Dの時間接続 | 比較の目的 |
|---|---|---|
| A | 保存済みの現行SLEAP serial追跡 | 基準 |
| B | Aの接続を前後の運動・曖昧性で監査し、疑わしい接続を切る | 全面置換せず改善できるか |
| C | 同じ全検出に対する独自の可変検出数・双方向追跡 | SLEAPの接続を使わず改善できるか |

検出点、calibration、後段の幾何、欠測の扱い、初期・境界条件を揃える。
後処理により誤りを増やした場面を見失わないよう、C28相当の再構成直後と、
C30/C34相当のID後処理後の両方で評価する。
まず現行λ=.767で機構を調べ、改善の一般的主張や採用判断の前には既存の全7λも確認する。
主区間20秒と失敗例は開発集合であり、閾値を決めた後に別の10–30秒を未使用の評価集合にする。

保存Aは全編serialの履歴を持つ。20秒だけSLEAPを新規起動した結果を同じ基準と呼ばない。
局所比較では前後の十分な文脈を同じ条件で与え、Aの再現と境界の影響を先に確認する。
安定な境界を取れない窓は文脈を拡張し、それでも不明なら局所試験としての制約を明示する。
各方式の任意の数値IDは直接比べず、同じ魚の検出が接続されるかを比べる。

### 3. 独自接続に必要な最小仕様

- 口＋胸びれの頑健な運動予測と、両方向の予測誤差を使う。
  進行方向に80度以上の移動は疑いの手掛かりとし、低速時・自然な旋回では角度単独で切らない。
- 次善の割当との差、観測からの経過時間、欠測を明示し、対応なしも許す。
  交差で同点に近い場合は短い候補列を残し、後続フレームから選び直す。
- 検出数が2や4でも処理する。実在3匹を理由に検出を上位3個へ減らさない。
  一匹が曖昧でも、他の二匹まで一括で新しいIDにしない。
- 尾の振動や部分的なノード交換を、魚全体のID交換と分ける。
  部位の質は測定できる情報だけで扱い、存在しないnode confidenceを作らない。
- trackletの切断理由、候補、コスト差、検出行の由来を保存する。
  3Dを使って2D接続を選び直す拡張は、2Dだけの条件とは別に報告する。

### 4. 判定基準と目視資料

評価の主対象は2Dの誤接続と最終3DのIDスワップ。
分断数、見失った時間、検出を保持した率、部位の混在も同時に測る。
接続を全部切ったり、座標を平滑化したりして見かけのスワップ数だけを下げる方式は改善としない。

今回スワップなしの76791/323819/77415を誤修正しないことを確認し、
ありの76235/76930/76988/31479と視点限定30735で実際の魚の継続性を見る。
レビューの対象側とイベント区間が確定する前に、これらを自動採点の完全な正解列にはしない。
femaleだけの既存指標やgated trackerの0スワップも、3匹の最終slot ID精度の代わりにはしない。

全3視点・全3匹のラベルを常に表示し、基準と候補の動画、入口・途中・出口の画像、
2D接続と3D IDの時系列を同じframe番号で提示する。
人が確認済みの範囲と機械的な診断を別々に残す。
